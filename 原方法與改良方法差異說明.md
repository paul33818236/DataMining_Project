# Original Method vs. Delayed3: Method Differences and Results

This document describes the retained R implementation and measured experimental results. The baseline is the linear-cost branch of the authors' public `scoth` implementation. Delayed3 is our extension of that branch. The main comparison does not represent the best result across every cost branch in the paper, and the reported numbers were measured from code rather than copied from the paper.

## 1. Main Changes

Delayed3 repairs sparse isolated spikes, reuses the authors' linear squared-error cost and changepoint scoring procedure, and extends hierarchical selection by suppressing nearby candidates in the first two levels and releasing them starting at level 3.

**The latest version does not use Huber loss or replace squared error with a new robust loss function.** Its resistance to isolated outliers comes primarily from fixed spike-repair preprocessing. Candidate selection and the threshold used in the main comparison also change.

## 2. Method Comparison

| Component | Original Linear Method | Delayed3 |
|---|---|---|
| Data | The authors' 42 public datasets | The same 42 datasets |
| Outlier handling | Use the original series directly | Repair qualifying isolated single-sample spikes first |
| Cost function | Linear squared error on the original series | The same linear squared error on a fixed repaired series |
| Changepoint scoring | Authors' Algorithm 1 | Reuse Algorithm 1 with the repaired-series cost interface |
| Hierarchical selection | Authors' Algorithm 2 | Extend the recursion with nearby-candidate suppression and delayed release |
| Nearby candidates | Follow the original selection rules | Candidates retained by the suppression mask are at least 3 samples apart in levels 1 and 2 |
| Level 3 onward | Continue the original recursion | Remove the suppression mask so blocked candidates can participate again |
| Main comparison threshold | 0.10 | 0.09 |
| Levels | 10 nonzero levels plus a level-0 control | The same |
| Multivariate data | Sum feature costs in the original units | Repair each feature separately, then sum costs in the original units |
| Segment-cost caching | Original calculation | The experiment entry point caches repeated segment costs |
| Authors' source | Run without modification | Implement changes in separate extension files without modifying upstream source |

## 3. Isolated-Spike Repair

Squared error amplifies extreme observations. An isolated spike can create unnecessary changepoints around a single event, so Delayed3 identifies and repairs qualifying observations before segmentation.

### 3.1 Noise-Scale Estimation

The noise scale is estimated using the median absolute deviation (MAD) of adjacent differences:

```text
sigma = median(abs(diff(x) - median(diff(x)))) / (qnorm(0.75) * sqrt(2))
```

When the MAD is close to zero, the implementation falls back to the smallest observed positive absolute difference, scaled by `1 / sqrt(12)`, and a numerical floor. This avoids a zero scale that could classify tiny changes as spikes. A robust scale estimate does not guarantee accurate noise identification for every type of series.

### 3.2 Repair Conditions

An interior observation qualifies for repair only when all the following conditions hold:

1. Its deviation from the average of its immediate neighbors exceeds `4 * sigma`.
2. The difference between those neighbors is at most `2.5 * sigma`.
3. The observation is above both neighbors or below both neighbors.
4. Neither adjacent position is also flagged as a spike candidate, protecting consecutive events from this repair rule.

A qualifying isolated observation is replaced by the average of its immediate neighbors. For example, when the conditions above hold:

```text
Original series: 10, 10, 50, 10, 10
Repaired series: 10, 10, 10, 10, 10
```

Series shorter than five observations are not repaired, and endpoints are never repaired. If qualifying isolated observations exceed 2% of the series length, repair is skipped for the entire series. For multivariate data, these rules are applied separately to each feature.

This strategy assumes sparse, isolated, single-sample contamination. A genuine single-sample event may still be removed, and the strategy may be unsuitable for dense contamination.

## 4. How Cost Computation Changes

The original method evaluates linear-fit squared error directly on the original observations in each segment. Delayed3 repairs the complete offline series once, then passes that fixed repaired series to the authors' original cost function.

```text
Original:
Original series -> Authors' linear cost -> Authors' scoring
                -> Original hierarchical selection

Delayed3:
Original series -> Isolated-spike repair -> Authors' linear cost and scoring
                -> Nearby-candidate suppression in levels 1 and 2
                -> Candidate release from level 3 -> Hierarchical partitions
```

Repair is not recomputed for each candidate segment. A given interval therefore always uses the same repaired observations and has the same deterministic cost, which also allows segment-cost caching.

An accurate description is an "isolated-spike-resistant cost-computation pipeline." It should not be described as replacing the authors' squared loss with Huber loss.

## 5. Nearby-Candidate Suppression and Delayed Release

### 5.1 Levels 1 and 2: Prioritize Strong, Separated Candidates

The implementation constructs a fixed retention mask from the initial candidate scores, processed from highest to lowest. Ties are resolved by index. A candidate is retained only if it is at least three samples away from every candidate already retained in the mask; otherwise, it is temporarily suppressed.

For example, if positions 20, 21, and 22 all have high scores and position 21 has the highest score, the mask prioritizes position 21 over its two neighbors in the early levels.

The first two levels apply this mask. Changepoints selected in earlier levels are preserved.

### 5.2 Level 3 Onward: Allow Previously Suppressed Candidates Back In

Starting at level 3, the nearby-candidate mask is removed. Previously suppressed candidates can participate again in the author-style recursive selection procedure. They must still pass the current selection threshold; release does not guarantee selection.

The intended effect is to identify major structure in early levels while allowing finer changes in later levels. Previously selected changepoints remain part of later partitions, preserving the nested hierarchy. This is an extension of Algorithm 2, not the unchanged original Algorithm 2.

## 6. Measured Results

Both methods use the same 42 datasets, the same representative ground-truth annotations, and a matching tolerance of plus or minus five samples. For the main comparison, each method uses a shared threshold across datasets, while ground-truth labels select the level with the highest F1 for each dataset.

| Metric | Original | Delayed3 | Difference: Delayed3 - Original |
|---|---:|---:|---:|
| Mean F1 | 0.7556 | 0.7913 | +0.0357 |
| F1-biased | 0.8490 | 0.8705 | +0.0216 |
| Covering | 0.7522 | 0.7625 | +0.0103 |
| Micro precision | 0.5894 | 0.6026 | +0.0132 |
| Micro recall | 0.8241 | 0.8704 | +0.0463 |
| True positives (TP) | 89 | 94 | +5 |
| False positives (FP) | 62 | 62 | 0 |
| False negatives (FN) | 19 | 14 | -5 |
| Mean runtime per dataset, seconds | 0.8067 | 0.8243 | +0.0176 |

Mean F1 increases by approximately 4.72% relative to the baseline. Across the 42 datasets, Delayed3 improves on 7, ties on 29, and declines on 6. The improvement is not universal.

Mean F1 is averaged across datasets. Micro precision and micro recall are computed from pooled changepoint counts, so they cannot be used to reconstruct the reported mean F1. F1-biased and covering are evaluated on the same predictions selected by F1; their settings are not optimized separately.

Timing uses the median of three runs per dataset on the same machine, followed by averaging across datasets. Cost caching is disabled for the timing comparison. Timing includes preprocessing, scoring, and selection of 10 levels, but excludes data loading, training-grid search, and metric calculation.

### Grouped Five-Fold Cross-Validation

| Level-Selection Rule | Original Linear F1 | Fixed Delayed3 F1 |
|---|---:|---:|
| Select the test level using ground-truth labels | 0.7414 | 0.7490 |
| Select a level on the training fold and hold it fixed on the test fold | 0.4591 | 0.4762 |

Datasets from the same source remain in the same fold. Thresholds and fixed levels are selected using the training folds. The first row still uses test labels for level selection. The second row is closer to a setting without test-label-based level selection, but performance is substantially lower. Since all datasets had already been inspected during development, both results remain exploratory internal validation.

## 7. Supported Conclusions and Limitations

1. Under the current 42-dataset comparison protocol, Delayed3 has higher mean F1 and fewer false negatives, with the same total false positives.
2. This version changes spike handling, candidate selection, and the main comparison threshold together. The full gain cannot be attributed to a single change; controlled ablations are needed to isolate individual contributions.
3. The main comparison selects the best level using ground-truth labels. It is not an estimate of performance with label-free level selection at deployment.
4. The descriptive source-group bootstrap 95% interval for the mean F1 difference is `[-0.0069, 0.0805]`. It includes zero, so a consistent statistically significant improvement has not been established.
5. The method and parameters were developed on repeatedly inspected data. External datasets not used in development are needed for further validation.
6. Isolated-spike repair does not address every anomaly type. Existing stress tests still show poor performance with 5% spike contamination.
7. The method uses a noise estimate from the complete series and observations on both sides of a point. It is an offline method, not directly a real-time streaming algorithm.

## 9. Suggested Method Summary for a Report

We propose Delayed3, an extension of the authors' linear-cost branch that combines isolated-spike repair with delayed candidate release. The method identifies sparse single-sample spikes using a robust scale estimate from adjacent differences, fixes the repaired series, and reuses the authors' linear squared-error cost and changepoint scoring procedure. Nearby candidates are suppressed in the first two hierarchical levels and released starting at the third level, allowing major structure to be selected before finer changes. In a descriptive comparison on the same 42 datasets, with a shared threshold per method and ground-truth-based level selection, mean F1 increases from 0.7556 to 0.7913, total false negatives decrease from 19 to 14, and total false positives remain at 62. These results require independent validation, and automatic selection of the final level remains unresolved.
